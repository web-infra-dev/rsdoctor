# Announcing Rsdoctor 2.0

import { BlogAuthors } from '@rstackjs/doc-ui/blog-authors';

<BlogAuthors />

We are excited to announce Rsdoctor 2.0! 🎉

Rsdoctor is a build analysis tool designed for Rspack. It helps developers investigate problems through visual reports and provides agents with data for automated diagnosis and optimization.

Highlights in this release include:

- [Build analysis for agents](#build-analysis-for-agents): Use the same analysis data for visual investigation by developers and automated analysis by agents
- [Smaller installation size](#a-smaller-package-and-dependency-graph): Reduce installation size by 56% and dependency count by 78%
- [Faster analysis](#faster-analysis): Reduce build analysis time by 57%
- [Faster rebuilds](#faster-rebuilds-in-watch-mode): Reduce analysis overhead during rebuilds, lowering HMR time by about **47%**
- [Improved multi-compiler support](#one-report-for-every-compiler): View analysis results for multiple compilers in one report

## Build analysis for agents

As agents take on more analysis, diagnosis, and optimization work, we want Rsdoctor to provide the build data they need to understand a project's build process and find opportunities to improve it.

Rsdoctor's visual interface primarily serves developers. To make the same data accessible to agents, we introduced [Agent CLI](/guide/start/ai#agent-cli) in Rsdoctor 1.x. It reads `rsdoctor-data.json` directly, supports searching and filtering report data, and returns structured JSON so agents can query what they need and investigate problems step by step.

In 2.0, Agent CLI is the recommended approach to automated analysis. The [Rsdoctor analysis skill](/guide/start/ai#agent-skills) helps agents choose query commands and interpret the results for their task. Start by installing Agent CLI in your project. You can also install the companion skill for your agent:

```bash
# Install Agent CLI
pnpm add -D @rsdoctor/agent-cli

# Install the Rsdoctor analysis skill (optional)
npx skills add rstackjs/agent-skills --skill rsdoctor-analysis
```

Next, configure [brief mode](/config/options/output#mode-brief) in the Rsdoctor plugin to generate `rsdoctor-data.json` for the agent to query:

```js
new RsdoctorRspackPlugin({
  output: {
    mode: 'brief',
    options: { type: ['json'] },
  },
});
```

Then run `pnpm run build`. For a one-off JSON output, you can also run `RSDOCTOR_OUTPUT=json pnpm run build`.

Once the report is generated, describe what you want to investigate in natural language:

```text
Use Rsdoctor to analyze this project and identify opportunities to reduce bundle size.
```

The agent chooses the relevant `rsdoctor-agent` commands and uses the project context to identify problems such as large chunks or duplicate dependencies. It can then query module issuer chains, loader timings, or tree-shaking bailouts to narrow down the cause and suggest optimizations.

With Agent CLI now serving as the entry point for agent analysis, we have retired the MCP Server workflow in Rsdoctor 2.0. Projects using `@rsdoctor/mcp-server` can follow the [2.0 migration guide](/guide/migration/migration-v2#ai-workflow-migration) to migrate.

## Smaller installation size \{#a-smaller-package-and-dependency-graph}

Rsdoctor 2.0 consolidates analysis capabilities previously spread across multiple packages into `@rsdoctor/core` and reduces runtime dependencies. This means fewer packages to download during installation and less disk usage in local development and CI environments.

These changes reduce the installation size from 25.5 MB to 11.1 MB and the dependency count from 83 to 18:

| Metric            | Rsdoctor 1.x | Rsdoctor 2.0 | Reduction rate |
| ----------------- | -----------: | -----------: | -------------: |
| Installation size |      25.5 MB |      11.1 MB |      **56.6%** |
| Dependency count  |           83 |           18 |      **78.3%** |

## Faster analysis

Since 1.5, Rsdoctor has used Rspack's native plugin to collect build data by default. Version 2.0 further simplifies the JavaScript implementation by moving more data collection logic to the native plugin. The [`experiments.enableNativePlugin`](/config/options/experiments#enablenativeplugin) option has also been removed.

These optimizations further reduce Rsdoctor's analysis overhead. In the benchmark, Rsdoctor 2.0 reduced analysis time by 57% compared with 1.4:

| Metric        | Rsdoctor 1.4 | Rsdoctor 2.0 | Reduction |
| ------------- | -----------: | -----------: | --------: |
| Analysis time |      18.07 s |       7.77 s | **57.0%** |
| Peak RSS      |    2,186 MiB |    1,755 MiB | **19.7%** |

## Faster rebuilds \{#faster-rebuilds-in-watch-mode}

When analyzing a project in watch mode, every rebuild should do as little extra work as possible. Rsdoctor 2.0 reduces this overhead in three ways:

- Reuse the SDK session and report server, and open the report page only for the first build.
- Preserve the bundler's loader cache and prevent loader events from accumulating across rebuilds.
- Skip module and asset gzip-size calculations. Non-watch builds retain the complete analysis path.

Watch mode writes report data with a faster compression level to reduce synchronous work on every update. As a trade-off, the compressed size of the main report shards increases by about 26%. This affects Rsdoctor report data only, not application bundle output. Non-watch builds continue to use the default compression level.

The benchmarks measure two different effects: HMR latency and the time spent on analysis during repeated builds.

| Benchmark metric                                     |   Before |   After | Reduction |
| ---------------------------------------------------- | -------: | ------: | --------: |
| Median HMR time                                      |   6.81 s |  3.64 s |   **47%** |
| Analysis time in a separate repeated-build benchmark | 250.9 ms | 14.2 ms | **94.3%** |

Actual gains depend on the project and build configuration.

## Improved multi-compiler support \{#one-report-for-every-compiler}

Rspack applications often create several compilers in one process. A multi-compiler configuration may build browser and Node.js targets together, Rsbuild environments may create separate web and server builds, and plugins may start child compilers for generated assets.

Rsdoctor 2.0 handles these scenarios through `RsdoctorRspackPlugin`, with each compiler's results available in the same report:

- [Multi-compiler and Rsbuild environments](https://github.com/web-infra-dev/rsdoctor/pull/1888): Group compilers created during the same startup and use environment names such as `web` and `node` to distinguish their results.
- [Child compilers](https://github.com/web-infra-dev/rsdoctor/pull/1842): Discover child compilers automatically and display their analysis data separately from the main compiler.

<img
  src="https://assets.rspack.rs/rsdoctor/child_compiler.png"
  alt="Compiler selector with Main compiler and child-assets marked Child"
  style={{ margin: 'auto' }}
/>

Automatic grouping is enabled by default and requires no new plugin. If one process starts unrelated compilers, set `multiCompiler: false`. A named group can also explicitly associate plugin instances:

```ts
new RsdoctorRspackPlugin({
  multiCompiler: { group: 'ssr' },
});
```

For querying a specific compiler through Agent CLI, see [Selecting a compiler](/guide/start/ai#selecting-a-compiler).

## Bundle analysis UI improvements \{#refined-bundle-analysis}

Large assets can contain thousands of modules across many nested directories. Rsdoctor 2.0 makes the Bundle Size page easier to navigate, from filtering assets and chunks to finding a module and inspecting its details.

Tree Graph uses virtual scrolling and render caching to keep large module trees responsive. It renders only nodes near the viewport and reduces tooltip and popover overhead while scrolling, making it smoother to expand folders and browse large assets.

**Before**

![Tree Graph before](https://assets.rspack.rs/rsdoctor/tree-graph-before.gif)

**After**

Treemap adds full-screen mode, a collapsible sidebar, breadcrumb navigation, and click-to-zoom so you can move between an overview and individual modules. It also unifies the Stat, Parsed, and Gzipped size metrics and adds JavaScript asset filtering and responsive layouts.

## How to upgrade

When upgrading to Rsdoctor 2.0, check these core changes:

- [Runtime requirements](/guide/migration/migration-v2#check-your-bundler): Node.js `^20.19.0 || >=22.12.0` and Rspack 2.0 or later are required.
- [Package name and module format](/guide/migration/migration-v2#update-the-rspack-plugin): Replace `@rsdoctor/rspack-plugin` with `@rsdoctor/core` and use ESM imports.
- [AI workflow](/guide/migration/migration-v2#ai-workflow-migration): Migrate from the removed `@rsdoctor/mcp-server` to Agent CLI.
- Rsdoctor 2.0 no longer supports webpack. Projects using webpack can continue using Rsdoctor 1.x.

See the [Rsdoctor 2.0 migration guide](/guide/migration/migration-v2) for the complete upgrade steps, configuration changes, and verification instructions. The guide also includes a migration skill that lets an agent help with the upgrade.

Try Rsdoctor 2.0 and share your feedback. See the [release page](https://github.com/web-infra-dev/rsdoctor/releases) for all changes.
