_2026 年 8 月_

# Rsdoctor 2.0 发布公告

我们很高兴地宣布 **Rsdoctor 2.0**！🎉

Rsdoctor 2.0 进一步聚焦 Rspack，并让构建报告成为可以被开发者、Agent 和自动化流程共同使用的数据。与当前 `v1.x` 分支相比，2.0 统一使用 Rspack 原生分析链路，覆盖更多 Compiler 场景，并通过更精简的包结构和依赖关系提供核心能力。

本次更新的主要亮点包括：

- **面向 Agent 的构建分析**：Agent CLI 与 Rsdoctor analysis skill 可以帮助 Coding Agent 查询构建数据，并给出可执行的优化建议。
- **一个报告覆盖所有 Compiler**：常规 Rspack 插件可以自动处理 MultiCompiler、Rsbuild environments 和 Child Compiler，同时保持每个 Compiler 的数据相互隔离。
- **默认使用 Rspack 原生链路**：Rsdoctor 2.0 要求使用 Rspack 2，并通过 Rspack 内置的 Rsdoctor Native Plugin 采集 Module Graph 和 Chunk Graph。
- **更精简的包结构**：Core、Graph、SDK、Utils 和 Rspack Plugin 统一收敛到 `@rsdoctor/core`，仓库 package 从 13 个减少到 6 个。
- **更轻量的安装与运行时**：直接 Runtime 依赖声明从 88 项减少到 39 项，同时继续通过预打包和依赖清理降低安装开销。

> Rsdoctor 2.0 要求使用 Node.js 22.18 及以上版本和 Rspack 2.0 及以上版本。webpack 项目请继续使用 Rsdoctor 1.x，或先迁移到 Rspack 再升级。

## 面向 Agent 的构建分析 {#build-analysis-for-agents}

Rsdoctor 报告包含 Asset、Module、Package、Loader 和 Tree Shaking 等多个维度的详细信息。在大型项目中，找到一个问题的答案仍可能需要在多个页面之间切换，再手动组合不同维度的数据。

Agent CLI 与 Rsdoctor analysis skill 最早在 1.x 期间推出，并在 2.0 中成为推荐的 AI 辅助分析工作流。[`@rsdoctor/agent-cli`](/guide/start/ai#agent-cli) 可以直接读取 `rsdoctor-data.json` 并返回结构化 JSON，让 Coding Agent 无需启动常驻服务即可检索和过滤报告数据。

```bash
# 安装 Agent CLI
pnpm add -D @rsdoctor/agent-cli

# 安装 Rsdoctor analysis skill（可选）
npx skills add rstackjs/agent-skills --skill rsdoctor-analysis

# 构建并生成 JSON 数据
RSDOCTOR_OUTPUT=json pnpm run build

# 获取整体优化建议
pnpm exec rsdoctor-agent bundle optimize --data-file ./dist/rsdoctor-data.json

# 查询指定数据工具
pnpm exec rsdoctor-agent query packages_duplicates --data-file ./dist/rsdoctor-data.json
```

Agent CLI 提供两类互补的使用方式：

- `list` 和 `query` 为 Agent 与自动化流程提供稳定、机器可读的工具目录与查询接口。
- `chunks`、`modules`、`packages`、`loaders`、`tree-shaking` 等分组命令适合交互式排查。

结合 analysis skill，Agent 可以逐步分析大 Chunk、重复依赖、Module 引用链、Loader 热点和 Tree Shaking 失败原因，并根据结果继续发起更聚焦的查询。

## 一个报告覆盖所有 Compiler {#one-report-for-every-compiler}

现代 Rspack 应用经常在同一进程中创建多个 Compiler。MultiCompiler 配置可能同时构建浏览器端和 Node.js 产物，Rsbuild environments 可能分别创建 Web 和 Server 构建，插件也可能通过 Child Compiler 生成自己的资源。

Rsdoctor 2.0 将常规的 `RsdoctorRspackPlugin` 统一为这些场景的入口：

- [MultiCompiler 与 Rsbuild environments 自动支持](https://github.com/web-infra-dev/rsdoctor/pull/1888)会聚合同一次启动中创建的 Compiler。每个 Compiler 都拥有独立的分析数据，报告中则提供切换入口，方便在不同结果之间浏览。Rsbuild environments 会直接使用 `web`、`node` 等 environment 名称。
- [Child Compiler 支持](https://github.com/web-infra-dev/rsdoctor/pull/1842)会在 Child Compiler 创建时自动发现它，并分别记录 Module Graph、Chunk、Asset、Loader、Plugin、诊断、规则和摘要数据。报告可以在 Main Compiler 与 Child Compiler 的结果之间切换。

主 Compiler 继续使用原有的 `.rsdoctor` 输出路径，其他 Compiler 的数据写入 `.rsdoctor/compilers/<compilerName>`，避免混合不同构建目标的数据。

自动聚合默认开启，无需引入新的插件。如果同一进程启动的是多个互不相关的 Compiler，可以设置 `multiCompiler: false`；也可以通过命名分组明确关联多个插件实例：

```ts
new RsdoctorRspackPlugin({
  multiCompiler: { group: 'ssr' },
});
```

浏览器端、服务端、Worker 和插件生成的构建可以分别拥有独立结果，用户不再需要切换到专用的 MultiCompiler Plugin。

## 默认使用 Rspack 原生链路 {#rspack-native-by-default}

Rsdoctor 1.x 同时支持 Rspack 和 webpack，Rspack Native Plugin 最初也是一条可选的性能优化链路。同时维护 Native、Stats、Rspack 和 webpack 多套实现，使分析流程难以持续保持一致。

Rsdoctor 2.0 仅支持 Rspack 2。Module Graph 与 Chunk Graph 始终通过 Rspack 内置的 Rsdoctor Native Plugin 采集，Resolver 分析直接使用 Rspack 内部的解析数据，Tree Shaking 所需的副作用源码也只会在相关分析开启时采集。

项目不再需要配置 `experiments.enableNativePlugin`，基于 Stats 的回退链路也已移除。统一的 Rspack 原生链路减少了重复处理，并让新的分析能力建立在一致的数据模型上。

webpack 支持与 `@rsdoctor/webpack-plugin` 已移除，webpack 项目可以继续使用长期维护的 `v1.x` 版本。

## 更小的包与依赖关系 {#a-smaller-package-and-dependency-graph}

Rsdoctor 1.x 将运行时能力拆分在 `utils`、`graph`、`sdk`、`types`、`components` 和不同 Bundler Plugin 等多个包中。这些边界增加了安装、构建、发布和版本同步成本。

Rsdoctor 2.0 围绕三类职责重新整理包结构：

- `@rsdoctor/core` 包含分析引擎、Graph 与 SDK 实现、通用工具和 Rspack Plugin。
- `@rsdoctor/shared` 提供 Node.js 与浏览器共享的类型、通用工具和图结构。
- `@rsdoctor/client`、`@rsdoctor/cli` 与 `@rsdoctor/agent-cli` 分别作为报告 UI、通用 CLI 和 Agent 工作流的独立入口。

当前 `v1.x` 与 `main` 分支之间的差异可以直接量化：

| 指标                  | Rsdoctor 1.x | Rsdoctor 2.0 |
| --------------------- | -----------: | -----------: |
| 仓库顶层 package      |           13 |            6 |
| Runtime 依赖声明      |           88 |           39 |
| 内部 Runtime 依赖关系 |           28 |            4 |
| 唯一外部 Runtime 依赖 |           51 |           30 |

依赖数量统计包含 `packages/*/package.json` 中直接声明的 `dependencies` 与 `optionalDependencies`，用于描述仓库的 package 关系，而不是单个应用安装后的完整传递依赖数量。

报告传输也从 Socket.IO 迁移到服务端 `ws` 与浏览器原生 WebSocket。常用依赖会在有助于降低安装开销时进行预打包，不再使用的 Runtime 依赖则已移除。

对于大多数 Rspack 项目，安装和导入路径需要从 `@rsdoctor/rspack-plugin` 更新为 `@rsdoctor/core`：

```ts title="Rsdoctor 1.x"
import { RsdoctorRspackPlugin } from '@rsdoctor/rspack-plugin';
```

```ts title="Rsdoctor 2.0"
import { RsdoctorRspackPlugin } from '@rsdoctor/core';
```

Rsdoctor 2.0 的 package 仅提供 ESM 产物。`@rsdoctor/cli` 继续提供 `rsdoctor` 命令，并保持独立安装。

## 更清晰的产物分析体验 {#refined-bundle-analysis}

在 1.x 分析模型的基础上，Rsdoctor 2.0 继续优化 Bundle Size 页面。Treemap 的布局、导航、响应式行为和体积展示得到调整，让大型 Asset 更容易查看；Bundle 分析也会在以 Module 为主的视图中过滤无关的资源类型，帮助用户更快定位 JavaScript 相关结果。

这些界面优化与 Rspack 原生 Module Graph、统一后的 Client Package 使用同一套数据模型，为 Overview、Tree Graph、Treemap 和 Module 详情页提供一致的数据基础。

## 升级到 2.0 {#upgrade-to-20}

Rsdoctor 2.0 包含以下不兼容更新：

- 要求使用 Node.js 22.18 及以上版本和 Rspack 2.0 及以上版本。
- 不再支持 webpack，并移除了 `@rsdoctor/webpack-plugin`。
- 使用 `@rsdoctor/core` 替换 `@rsdoctor/rspack-plugin`。
- Package 仅提供 ESM 产物，需要将 CommonJS `require()` 调用改为 ESM Import。
- 删除 `experiments.enableNativePlugin`，原生分析链路现在始终启用。
- 使用 `@rsdoctor/agent-cli` 替换基于 `@rsdoctor/mcp-server` 的工作流。
- 将已废弃的 `mode`、`brief`、`lite` 和 `output.compressData` 配置迁移到 2.0 的 Output 结构。

```bash
pnpm remove @rsdoctor/rspack-plugin
pnpm add -D @rsdoctor/core
```

使用 CLI 时，请确保 `@rsdoctor/cli` 与 `@rsdoctor/core` 的版本一致。
