# Rsdoctor 2.0 发布公告

import { BlogAuthors } from '@rstackjs/doc-ui/blog-authors';

<BlogAuthors />

我们很高兴地宣布 **Rsdoctor 2.0 正式发布**！🎉

Rsdoctor 2.0 将聚焦 Rspack，利用其原生能力加快构建分析，并通过精简依赖将安装体积减少 56%。同时，2.0 改善了 agent 支持，让同一份构建数据既能用于开发者的可视化排查，也能用于 agent 的自动化分析。

随着这一调整，Rsdoctor 2.0 将不再兼容 webpack，使用 webpack 的项目可以继续使用 Rsdoctor 1.x。

本次更新的主要亮点包括：

- [更快的分析速度](#faster-analysis)：默认启用原生分析能力，减少 JavaScript 侧的重复数据处理。
- [面向 agent 的构建分析](#build-analysis-for-agents)：通过 Agent CLI 与 Rsdoctor analysis skill，让 agent 直接查询数据、排查构建问题。
- [更小的安装体积](#a-smaller-package-and-dependency-graph)：合并包结构、精简运行时依赖，第三方依赖体积减少 **56.6%**。
- [更快的增量构建](#faster-rebuilds-in-watch-mode)：保留 loader 缓存并减少分析开销，在基准测试中，HMR 耗时中位数降低约 **47%**。
- [改进多 Compiler 支持](#one-report-for-every-compiler)：在同一份报告中查看多个 compiler 的分析结果。

## 更快的分析速度 \{#faster-analysis}

Rsdoctor 1.x 同时支持 Rspack 和 webpack，部分分析能力需要依赖两者都能提供的数据。2.0 聚焦 Rspack 后，可以直接利用更多 Rspack 内部数据。

Rspack native plugin 将耗时较长的数据处理交给 Rspack 内部的 Rust 实现。它在 Rsdoctor 1.0 中作为可选优化推出，在当时的大型项目测试中将整体分析时间减少了 **20% 以上**。Rsdoctor 2.0 默认启用这项能力。

模块图和 chunk 图现在直接由 Rspack 提供，无需经过 stats 转换。Resolver 分析复用 Rspack 内部的解析数据，副作用源码也只在启用 tree shaking 分析时采集，从而减少 JavaScript 侧的数据转换和重复处理。

项目不再需要配置 [`experiments.enableNativePlugin`](/config/options/experiments#enablenativeplugin)，升级到 2.0 后删除该配置即可。

## 面向 agent 的构建分析 \{#build-analysis-for-agents}

排查构建问题时，往往需要在多个报告页面之间切换，关联产物、模块和依赖信息。Agent CLI 让 agent 可以直接查询这些数据，并根据发现继续追查。

Agent CLI 与 Rsdoctor analysis skill 在 1.x 中首次推出，现在成为推荐的 AI 辅助分析工作流。[`@rsdoctor/agent-cli`](/guide/start/ai#agent-cli) 可以直接读取 `rsdoctor-data.json` 并返回结构化 JSON，让 agent 无需启动常驻服务即可检索和过滤报告数据。

```bash
# 安装 Agent CLI
pnpm add -D @rsdoctor/agent-cli

# 安装 Rsdoctor analysis skill（可选）
npx skills add rstackjs/agent-skills --skill rsdoctor-analysis
```

推荐在 Rsdoctor 插件中配置 [brief 模式](/config/options/output#mode-brief)，生成 `rsdoctor-data.json`：

```js
new RsdoctorRspackPlugin({
  output: {
    mode: 'brief',
    options: { type: ['json'] },
  },
});
```

配置后运行 `pnpm run build`。临时生成 JSON 数据时，也可以使用 `RSDOCTOR_OUTPUT=json pnpm run build`。

生成报告后，就可以让 agent 开始分析：

```text
使用 Rsdoctor 分析当前项目，找出可以优化产物体积的方向。
```

agent 会调用相应的 `rsdoctor-agent` 命令，结合项目上下文分析大 chunk、重复依赖、模块引用链、耗时较长的 loader 和 tree shaking 失败原因，并根据结果进一步缩小排查范围。

<img
  src="https://assets.rspack.rs/others/assets/rsdoctor/agent-cli-2.gif"
  alt="Agent CLI 演示"
  style={{ margin: 'auto' }}
/>

Rsdoctor 2.0 使用 Agent CLI 替代 `@rsdoctor/mcp-server`，按需执行，无需维持服务连接。具体用法请参考 [AI 分析指南](/guide/start/ai)；已有 MCP 工作流的迁移方式见 [2.0 迁移指南](/guide/migration/migration-v2#ai-工作流迁移)。

## 更小的安装体积 \{#a-smaller-package-and-dependency-graph}

Rsdoctor 2.0 将原先分散在多个包中的核心分析能力整合到 `@rsdoctor/core`，并精简运行时依赖。这减少了安装时需要下载的包数量，也降低了本地开发和 CI 环境中的磁盘占用。

经过这些调整，Rsdoctor 2.0 的安装体积从 25.5 MB 降至 11.1 MB，依赖数量从 83 个减少到 18 个：

| 指标     | Rsdoctor 1.x | Rsdoctor 2.0 |      降幅 |
| -------- | -----------: | -----------: | --------: |
| 安装体积 |      25.5 MB |      11.1 MB | **56.6%** |
| 依赖数量 |           83 |           18 | **78.3%** |

## 更快的增量构建 \{#faster-rebuilds-in-watch-mode}

在 watch 模式下分析项目时，每次重新构建都应尽量减少额外开销。Rsdoctor 2.0 为此进行了三项优化：

- 复用 SDK 会话和报告服务，并让报告页面仅在首次构建时打开。
- 保留构建工具的 loader 缓存，并避免 loader 事件在重复构建中累积。
- 跳过模块和产物的 gzip 体积计算；非 watch 构建仍保留完整分析。

watch 模式会使用更快的压缩级别写入报告数据，以减少每次更新的同步写入耗时。作为取舍，主要报告分片的压缩后体积会增大约 26%。这一变化只影响 Rsdoctor 报告数据，不影响应用构建产物；非 watch 构建仍使用默认压缩级别。

两组基准测试分别衡量了 HMR 延迟和重复构建中的分析耗时：

| 基准测试指标                   |   优化前 |  优化后 |  耗时降幅 |
| ------------------------------ | -------: | ------: | --------: |
| HMR 耗时中位数                 |   6.81 s |  3.64 s |   **47%** |
| 另一组重复构建基准中的分析耗时 | 250.9 ms | 14.2 ms | **94.3%** |

实际收益取决于项目规模和构建配置。

## 改进多 Compiler 支持 \{#one-report-for-every-compiler}

Rspack 应用经常在同一进程中创建多个 compiler。multi-compiler 配置可能同时构建浏览器端和 Node.js 产物，Rsbuild environments 可能分别创建 web 和 server 构建，插件也可能通过 child compiler 生成自己的资源。

Rsdoctor 2.0 通过 `RsdoctorRspackPlugin` 支持这些场景，在同一份报告中分别展示各个 compiler 的结果：

- [multi-compiler 与 Rsbuild environments](https://github.com/web-infra-dev/rsdoctor/pull/1888)：自动聚合同一次启动中创建的 compiler，并使用 `web`、`node` 等 environment 名称区分结果。
- [child compiler](https://github.com/web-infra-dev/rsdoctor/pull/1842)：自动发现 child compiler，并将其分析数据与 main compiler 隔离展示。

<img
  src="https://assets.rspack.rs/rsdoctor/child_compiler.png"
  alt="包含 main compiler 和带 Child 标签的 child-assets 的 compiler 选择器"
  style={{ margin: 'auto' }}
/>

自动聚合默认开启，无需引入新的插件。如果同一进程启动的是多个互不相关的 compiler，可以设置 `multiCompiler: false`；也可以通过命名分组明确关联多个插件实例：

```ts
new RsdoctorRspackPlugin({
  multiCompiler: { group: 'ssr' },
});
```

通过 Agent CLI 查询指定 compiler 的方式，见[选择 compiler](/zh/guide/start/ai#selecting-a-compiler)。

## 产物分析界面改进 \{#refined-bundle-analysis}

大型产物可能包含分布在多层目录中的数千个模块。Rsdoctor 2.0 改善了 Bundle Size 页面的浏览体验，让你更方便地筛选产物和 chunk、定位模块并查看详情。

Tree Graph 通过虚拟滚动和渲染缓存，让大型模块树保持流畅。它只渲染视窗附近的节点，并减少滚动时提示框、弹出层等交互组件的开销，改善展开目录和连续浏览大型产物时的体验。

**优化前**

![Tree Graph 优化前](https://assets.rspack.rs/rsdoctor/tree-graph-before.gif)

**优化后**

![Tree Graph 优化后](https://assets.rspack.rs/rsdoctor/tree-graph-after.gif)

Treemap 新增全屏模式、可收起的侧边栏、面包屑导航和点击缩放，方便在整体概览与具体模块之间切换。同时，它统一了 Stat、Parsed 和 Gzipped 体积指标，并支持 JavaScript 产物筛选和响应式布局。

> 相关 PR：[#1705](https://github.com/web-infra-dev/rsdoctor/pull/1705)、[#1782](https://github.com/web-infra-dev/rsdoctor/pull/1782)、[#1830](https://github.com/web-infra-dev/rsdoctor/pull/1830)、[#1839](https://github.com/web-infra-dev/rsdoctor/pull/1839)。

## 如何升级 \{#how-to-upgrade}

升级到 Rsdoctor 2.0 时，主要需要关注以下变化：

- [运行环境](/zh/guide/migration/migration-v2#检查构建工具)：要求 Node.js `^20.19.0 || >=22.12.0` 和 Rspack 2.0 及以上版本。
- [包名与模块格式](/zh/guide/migration/migration-v2#更新-rspack-插件)：使用 `@rsdoctor/core` 替换 `@rsdoctor/rspack-plugin`，并使用 ESM 导入。
- [AI 工作流](/zh/guide/migration/migration-v2#ai-工作流迁移)：从已移除的 `@rsdoctor/mcp-server` 迁移到 Agent CLI。

完整的升级步骤、配置变更和验证方法，请参考 [Rsdoctor 2.0 升级指南](/zh/guide/migration/migration-v2)。指南也提供了迁移 skill，可让 agent 协助完成升级。

欢迎试用 Rsdoctor 2.0 并分享反馈，完整更新内容见 [release 页面](https://github.com/web-infra-dev/rsdoctor/releases)。
